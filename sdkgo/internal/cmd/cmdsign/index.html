📐 Flow 2: Fixed Binary Layouts & Wire Formats

A. 89-Byte Binary Signature Envelope (SigEnvelope)

Used for requests to downstream services (combined with access token as X-I6-Signature: <envelope>.<token>):

Type & Flags 1 Byte (uint8) [0:1] 0x02 | 0x80
Exp (Epoch Sec) 8 Bytes (uint64 BE) [1:9]
Nonce Buffer 16 Bytes [9:25]
Ed25519 Digital Signature 64 Bytes [25:89]

• Wire Encoding: 89 bytes × 4/3 = 119 unpadded Base64URL characters.
• Token Theft Immunity: The access token embeds the client's public key; if stolen without the private key, signatures cannot be forged.

B. 121-Byte Binary Refresh Assertion (RefreshAssertion)

Used for unattended token renewal at POST /api/userz/refresh-dataset (embeds client public key):

Type & Flags 1 Byte (uint8) [0:1] 0x03 | 0x80
Exp (Epoch Sec) 8 Bytes (uint64 BE) [1:9]
Nonce Buffer 16 Bytes [9:25]
Client Public Key (JTI) 32 Bytes [25:57]
Ed25519 Digital Signature 64 Bytes [57:121]

• Wire Encoding: 121 bytes × 4/3 = 162 unpadded Base64URL characters.
• Self-Contained Proof: Proves ownership of the refresh credential without requiring an existing access token.

⚡ Command-Line Quickstart

Run Directly via Go CLI

No build required; run directly from the i6sdk workspace root:

# 1. Generate a test Ed25519 keypair:
go run ./main.go sign keygen

# 2. Sign an HTTP request to a downstream microservice:
go run ./main.go sign request \
  --key @privkey.txt \
  --url "https://api.infinity6.ai/api/datasetmanager/data?limit=10" \
  --token "<access_token>"

# 3. Output only the raw header for shell scripting:
SIG=$(go run ./main.go sign request -k @key.txt -u /api/data -t <token> --quiet)
curl -H "X-I6-Signature: $SIG" https://api.infinity6.ai/api/data

# 4. Sign a standalone refresh assertion for unattended machine renewal:
ASSERTION=$(go run ./main.go sign assertion -k @key.txt --quiet)
curl -X POST https://api.infinity6.ai/api/userz/refresh-dataset \
  -H "X-I6-Signature: $ASSERTION" \
  -H "Content-Type: application/json" \
  -d '{"dataset":"ds-sales"}'
